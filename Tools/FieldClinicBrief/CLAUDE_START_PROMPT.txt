# КОМАНДА ДЛЯ CLAUDE CODE — FIELD CLINIC

Работай как автономный технический руководитель и Unity-разработчик в ОТКРЫТОЙ ЛОКАЛЬНОЙ папке моего проекта. К сообщению приложен `FIELD_CLINIC_FOR_CLAUDE.zip` либо этот архив уже лежит в папке проекта/рабочего каталога. Найди его доступным тебе файловым инструментом. Не проси меня распаковывать архив вручную: проверь содержимое и безопасно извлеки его сам.

ВАЖНО: действуй, а не просто составляй план. Первым делом открой `FIELD_CLINIC_FOR_CLAUDE/00_AUTOSTART.md` из архива и выполни инструкции В УКАЗАННОМ ПОРЯДКЕ. Затем используй `01_SETUP_REFERENCE.md`, `02_FULL_GAME_BRIEF.md`, `03_REPOSITORIES.json`, `skills/` и `04_RESUME.md` по мере необходимости. Не читай весь 90-КБ игровой бриф до проверки того, что это локальная среда с доступом к Unity.

Контекст: Unity, Blender, RTX 5070 Ti Gaming Trio, 32 ГБ DDR5, опыт в геймдеве нулевой. У меня уже есть Claude и Codex с большими лимитами; НЕ устанавливай новые AI-агенты, локальные LLM, Ollama, ComfyUI или веса генеративных моделей. Игра — одиночный 3D open-world с низкополигональным стилизованным миром: игрок от первого лица ловит пациентов, везёт их на машине на свою базу и проводит вымышленные игровые операции. За рулём переключаемые первая и третья камеры.

Твоя цель — самостоятельно настроить текущий проект, девять project skills и доступ к Unity и Blender, выбрать полезные проверенные зависимости из 47 источников и начать РЕАЛЬНЫЙ вертикальный срез: небольшая карта → управление пешком → машина → пациент → перевозка → база → операция → сохранение. Добавляй плагины по необходимости, не все подряд. Приоритет — игровой процесс, авторская атмосфера, low-poly, производительность и звуковые реакции на события.

Проверь наличие папки `Assets/Packages/ProjectSettings` и работающего редактора. Если проекта нет — предложи/создай через доступный Unity Hub/CLI подходящий URP-проект, не меняя имеющиеся проекты. Используй официальный Unity agent plugin/skills и один рабочий канал управления редактором (Unity CLI + Unity Pipeline; Coplay Unity MCP только как резерв). Для Blender используй mcp-for-blender или проверяемый Blender Python в локальном установленном Blender. Мосты и CLI — это НЕ локальные нейросети. Запиши фактическую проверку работы обеих программ.

Никаких покупок, платных API, публикации репозитория, переустановки уже работающих программ, удаления чужих файлов, массовой загрузки всех библиотек или обхода подтверждений системы. Перед изменениями сохрани исходное состояние, конфиги и .meta. Действительно проверяй лицензии и совместимость Unity 6/URP, импортируй зависимости по одной. Не запускай удалённые shell-скрипты вслепую, не делай публичных серверов, не выводи секреты. Если нужен мой вход в Unity Hub, одноразовое системное подтверждение или выбор папки, напиши ОДНО конкретное действие и после него продолжи; не выдавай блокировку за успех.

Отдельно подготовь общие project rules и skills для Codex, но НЕ утверждай, что Codex протестирован, пока не получишь доступ к его действительной сессии. Ты ведущий исполнитель, Codex — возможный последующий ревьюер.

Делай по этапам с проверкой. Сохраняй результаты в `Docs/EnvironmentReport.md`, `Docs/SetupReport.md`, `Docs/DependencyDecisions.md`, `Docs/Progress.md`, `Docs/NextAction.md`. Для тестов ставь только PASS, FAIL, BLOCKED или NOT RUN с доказательствами. Если связь с локальным редактором недоступна (например, ты оказался в обычном облачном чате), прямо сообщи об этом: прикреплённый ZIP не создаёт доступ к моему ПК. Объясни, как продолжить в Claude Code с этой папкой, и подготовь всё возможное без ложных утверждений.

НАЧНИ СЕЙЧАС: найди ZIP → извлеки → прочитай `00_AUTOSTART.md` → проверь среду → настрой skills и мосты → выполни проверочные сцены → переходи к минимальной игре. Не останавливайся на списке ссылок и не спрашивай уже известные вводные.
