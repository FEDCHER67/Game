# Field Clinic — сначала подключение и проверка среды

Это дополнительное задание для уже установленного Claude Code или Codex с локальным доступом к проекту. Оно не является установщиком и не содержит готовых игровых компонентов.
Инструкции по подключению сверены с первоисточниками 13 октября 2026 года. На компьютере пользователя они ещё не выполнялись.

## Задача текущей сессии

Выполни только настройку рабочей среды и проверку связи. Не начинай создание полного игрового мира.
Этот файл имеет приоритет над требованием немедленно разрабатывать игру из основного промпта — только в части объёма текущей сессии. Его запреты на разрушительные действия, локальные модели и платные сервисы остаются в силе.

Контекст известен: Unity, Blender, нулевой опыт пользователя, RTX 5070 Ti Gaming Trio, 32 ГБ DDR5. Игра: открытый мир, поимка пациентов, перевозка на машине, база и игровые операции; первое лицо пешком, переключаемая камера за рулём. Не запрашивай эти сведения повторно. Обнаружь ОС и фактические программы; пример Windows-пути ниже не доказывает наличие именно такого каталога.

## 1. Обнаружь проект, клиента и исходный набор

Работай в открытой папке Unity-проекта: в ней должны быть Assets, Packages и ProjectSettings/ProjectVersion.txt.
Исходный набор предполагается в Tools/UNITY_FIELD_CLINIC_KIT/:
- UNITY_FIELD_CLINIC_PROMPT.md;
- repository-manifest.json;
- skills/ с девятью каталогами fc-*.

Если путь отличается, найди набор внутри разрешённой рабочей папки, а не сканируй весь домашний каталог.
Прочитай существующие AGENTS.md, CLAUDE.md, основной промпт, manifest и fc-project-bootstrap/SKILL.md.
Определи, где выполняются команды: этот Windows-компьютер, WSL, удалённая машина или облачный контейнер. Доступ к Git-репозиторию не равен доступу к открытому домашнему Unity.

Проверь версию Unity, render pipeline, Git status, доступность терминала, Blender, uv/uvx, Unity CLI и существующих интеграций. Не выводи ключи и содержимое файлов авторизации.
Создай Docs/EnvironmentReport.md с фактическими данными. Не мигрируй существующий проект и не ставь другую версию редактора автоматически.

## 2. Защити исходное состояние

Не меняй существующие несохранённые сцены. До первых изменений сохрани контрольную точку: Git для уже настроенного репозитория либо отдельную резервную копию исходников, Packages и ProjectSettings без Library, Temp, кешей и секретов.
Если Git ещё не настроен, подготовь Unity .gitignore и локальный репозиторий. Для коммита не выдумывай имя и email пользователя; при отсутствии идентичности используй резервную копию и отметь ограничение.
Не публикуй проект и не подключай удалённый репозиторий без отдельного поручения.
Никогда не выполняй reset --hard, git clean, force push и массовое удаление.

## 3. Подключи девять проектных skills для обоих клиентов

Сохрани исходники в Tools/UNITY_FIELD_CLINIC_KIT/skills/.
Скопируй каждую папку fc-* целиком:
- в .claude/skills/<имя>/SKILL.md для Claude Code;
- в .agents/skills/<имя>/SKILL.md для Codex.

Это каталоги в корне Unity-проекта, не внутри Assets. Не создавай лишний уровень skills/skills.
Перед заменой существующих файлов сравни содержимое; пользовательские версии не перезаписывай. Зафиксируй конфликты и предложи безопасное объединение.
Создай Docs/AgentRules.md как единый источник общих правил. В существующие AGENTS.md и CLAUDE.md аккуратно добавь указание читать его и точный путь основного промпта. Не заменяй их целиком.
Общие правила: изменения небольшими этапами; один активный редактор проекта за раз; версии зависимостей фиксируются; .meta сохраняются; никаких платных API и локальных моделей; результаты проверок не выдумываются.
Проверяй загрузку skills отдельно в каждом реально доступном клиенте. Создание каталога не доказывает, что другой клиент уже их загрузил.

## 4. Подключи Unity через один канал

Основной путь: Unity official agent plugin/skills + Unity CLI.
Первичные источники:
https://github.com/Unity-Technologies/unity-agent-plugin
https://docs.unity.com/en-us/ai/unity-plugin/claude-code
https://docs.unity.com/en-us/ai/unity-plugin/codex
https://docs.unity.com/en-us/unity-cli/use-unity-cli

Сначала используй уже установленное. Проверь unity --version и unity doctor.
Если Unity CLI отсутствует, в Windows доступен официальный документированный путь:
winget install --id Unity.CLI -e
Не дублируй установленный через Hub экземпляр и не выполняй интернет-скрипты через pipe-to-shell.

Для установленных standalone CLI документированы команды:
claude plugin marketplace add Unity-Technologies/unity-agent-plugin
claude plugin install unity@unity-agent-plugin
codex plugin marketplace add Unity-Technologies/unity-agent-plugin
codex plugin add unity@unity-agent-plugin

До выполнения проверь наличие соответствующей команды и поддерживаемый синтаксис. Расширение VS Code не гарантирует команду claude/codex в PATH.
Если клиент доступен только как расширение, не устанавливай второй клиент ради этих команд. Используй поддерживаемую установку плагина через интерфейс или ручное подключение нужных официальных skills, описанное в README: сохрани репозиторий вне Assets, зафиксируй commit и перенеси нужные каталоги вместе с references в проектные пути клиента. Не подключай одновременно плагин и дублирующие его skills.
Не добавляй рекламные, платёжные и сетевые функции из каталога: они не нужны нашей игре.

По текущей документации Unity CLI настрой маленький editor-пакет для связи с открытым редактором. Проверь его фактическое имя, версию и требования; не угадывай UPM URL.
Проверь, что выбранный Unity Editor открыт именно на текущую папку, а не на другой проект/worktree.
Coplay Unity MCP — резервный путь, только если основной заблокирован; не устанавливай оба сразу:
https://github.com/CoplayDev/unity-mcp
Не включай необязательную облачную генерацию ассетов и не открывай сервер наружу.

## 5. Подключи Blender

Первичный источник:
https://github.com/ahujasid/mcp-for-blender

Это локальный программный мост к Blender, не локальная нейросетевая модель.
Не подключай Premium, внешние генеративные API и аккаунты библиотек ассетов.
Прочитай актуальный README и сведения о пакете до установки; сохрани применённую версию и команды.

Если uv отсутствует, документированная установка для Windows:
winget install --id astral-sh.uv -e

В актуальном README есть интерактивная настройка:
uvx mcp-for-blender setup

Она меняет конфигурации клиентов и устанавливает аддон. До выполнения проверь существующие настройки и резервные копии. Запускай её только в доступном интерактивном терминале; не объявляй её завершённой, если она ждёт выбора человека.
Для ручного пути README описывает install-addon и регистрацию MCP в каждом клиенте. Не перезаписывай весь config ради одного сервера. Используй абсолютный путь uvx.exe, если GUI не видит команду.

Установи DISABLE_TELEMETRY=true в окружении запуска этого MCP для каждого настроенного клиента; не включай согласие на передачу содержимого. При доступной настройке оставь локальное подключение, без публичных адресов и проброса портов.
После установки попроси пользователя перезапустить нужный клиент и открыть Blender, только если это действительно нельзя сделать доступными инструментами.
Не запускай Blender MCP одновременно из двух AI-клиентов. При переключении сначала отключи соединение предыдущего.

## 6. Выполни настоящие тесты

Сначала проверь текущего клиента. Второму подготовь те же проектные инструкции и конфигурацию, но не выдавай его тест за выполненный без реальной сессии.

A. Файлы: прочитай ProjectVersion.txt и Packages/manifest.json; покажи фактическую версию и наличие URP.
B. Skills: у текущего клиента проверь доступность fc-project-bootstrap; остальные проверь по именам. Отдельно отметь, проверен ли второй клиент.
C. Unity: сохрани новую сцену Assets/_Game/Scenes/FC_ConnectionTest.unity, не заменяя существующую. Создай куб FC_UnityConnectionTest, измени Transform, запроси данные обратно и сохрани сцену. Прочитай Console; отдели новые ошибки от исходных.
D. Blender: только в отдельной коллекции FC_ConnectionTest создай простой ящик заданного размера. Получи изображение viewport доступным инструментом и сохрани .blend в ArtSource/ConnectionTest/. Не удаляй чужие объекты.
E. Связка Blender→Unity: экспортируй тестовый объект в FBX в Assets/_Game/Art/ConnectionTest/, проверь появление модели в Unity, размер, материал и отсутствие новых ошибок. Не используй .blend внутри Assets как единственный путь обмена.
F. Состояние после перезапуска: если реально выполнено, перепроверь обнаружение инструментов. Иначе NOT RUN.

Для каждого теста укажи PASS, FAIL, BLOCKED или NOT RUN. PASS означает реально выполненную проверку. Файл отчёта или наличие установки не доказывает работу редактора. Не называй render Blender скриншотом игры.

## 7. Заверши текущий этап

Оставь:
- Docs/EnvironmentReport.md;
- Docs/SetupReport.md — компоненты, версии, пути, изменения конфигурации, тесты и ограничения;
- Docs/AgentRules.md и аккуратные ссылки из AGENTS.md/CLAUDE.md;
- Docs/NextAction.md — точная следующая задача, начинающаяся с разработки только после подтверждения связи;
- тестовые файлы, контрольную точку и журнал фактически выполненных команд без секретов.

Не скачивай сейчас все 34 репозитория, все ассеты или звуковые архивы. Игровые пакеты подключаются по необходимости после этого этапа.
Если требуется ручное действие в GUI, дай точный путь меню и ожидаемый результат, а не общую просьбу «настрой всё». До него выполни всё доступное. Не подменяй настройку одним планом.

Отчёт пользователю — по-русски: что подключено, в каком именно клиенте проверено, какую сцену открыть и какие проверки заблокированы. Не обещай продолжение после закрытия сессии.
