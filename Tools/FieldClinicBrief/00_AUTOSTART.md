# 00 — AUTOSTART: автономный запуск набора Field Clinic в Claude Code

**Действуй по шагам.** Это главный управляющий документ набора. Файлы здесь — контекст/skills/ссылки, а НЕ скачанные плагины и НЕ готовые сцены. Предыдущий план `01_SETUP_REFERENCE.md` служит подробным справочником для этапа A; его фраза «не начинай игру в этой сессии» относится к старому отдельному запуску и здесь переопределена: после успешного этапа A переходи к B и C. Все его ограничения на безопасность сохраняются.

## Миссия и контекст

Пользователь без опыта в Unity, с Blender и ПК RTX 5070 Ti Gaming Trio, 32 ГБ DDR5. Использует существующие Claude Code и Codex, не хочет никаких новых локальных AI-агентов и генеративных нейромоделей. Unity, URP для нового проекта; существующую версию и pipeline не меняй автоматически.

3D одиночная игра с открытым миром. Персонаж ходит от первого лица; едет на машине с переключаемой камерой (первое/третье лицо), ловит пациентов, загружает в авто, доставляет на базу, проводит стилизованные вымышленные операции. Не подменяй игру симулятором скорой помощи и не добавляй реалистичных медицинских процедур. Хочется собственная атмосфера, хорошие оптимизированные low-poly модели, дороги, интерактив, звук и стабильный FPS. Первый milestone — **один полностью работающий квартал и одна завершённая цепочка действий**.

## 0. Предварительные проверки — не перепрыгивать

1. Определи фактический режим исполнения: локальный Claude Code в текущей ОС, Claude Desktop с доступом к папке, контейнер или облачный чат. Проверь реальные инструменты файлов, терминала, доступа к редактору и сети. Наличие Git-клона не означает доступа к домашнему Unity.
2. Найди Unity-проект в открытой/разрешённой рабочей папке (не сканируй весь диск). Структура: `Assets/`, `Packages/`, `ProjectSettings/ProjectVersion.txt`. Если проекта нет, найди Unity Hub/Unity CLI и предложи/создай новый Unity 6 LTS URP-проект только в разрешённой папке; если ОС/лицензия требуют интерфейсного действия, дай пользователю единственную точную инструкцию.
3. Пакет: `01_SETUP_REFERENCE.md`, `02_FULL_GAME_BRIEF.md`, `03_REPOSITORIES.json`, `skills/` и остальные файлы набора. Размести извлечённую копию в `<UnityRoot>/Tools/FieldClinicBrief/`, если она пока находится вне проекта; не размещай её в `Assets`. Если изначально ZIP уже в папке Unity, не размножай копии без необходимости.
4. Прочитай проектные `CLAUDE.md`, `AGENTS.md`, `Packages/manifest.json`, `Packages/packages-lock.json` (если есть), `ProjectSettings/ProjectVersion.txt`, Git status. Проверь версию редактора, pipeline, существующие ошибки и программы. Не выписывай секреты.
5. Прежде чем менять проект: сделай разумную локальную контрольную точку — git commit при существующем настроенном репозитории или ограниченная резервная копия важных файлов; не подставляй выдуманную Git-identity, не включай `Library`, `Temp`, `.env`, ключи или крупные кеши. Сохрани `Docs/EnvironmentReport.md`.

## A. Подключить Claude ↔ Unity и Claude ↔ Blender и установить skills

1. Настрой девять `fc-*` skills из `skills/` внутри проекта: `.claude/skills/<имя>/SKILL.md`. В `.agents/skills/<имя>/SKILL.md` подготовь те же копии для Codex. Не заменяй существующие пользовательские skills, записывай checksum и корректно обрабатывай конфликты. Проверь, что текущий Claude их видит, а Codex пометь UNVERIFIED без отдельного запуска. Оригиналы останутся в `Tools/FieldClinicBrief/skills`.
2. Создай `Docs/AgentRules.md`, сошлись на него в существующих `CLAUDE.md`/`AGENTS.md`, не удаляй их прежнее содержимое. Правила: проверка сцен вместо одной генерации кода; одна система каждой категории; лицензии/версии; сохранение `.meta`; безопасность; фокус на первом игровом цикле.
3. Подключи официальный **Unity agent plugin/skills** для имеющегося Claude Code: https://github.com/Unity-Technologies/unity-agent-plugin и https://docs.unity.com/en-us/ai/unity-plugin/claude-code . Этот plugin — навыки клиента, НЕ пакет Unity и НЕ сам мост к Editor. В Claude Code есть вариант slash-команд `/plugin marketplace add Unity-Technologies/unity-agent-plugin`, затем `/plugin install unity@unity-agent-plugin`; корректный способ выбирай по реально доступному клиенту. Не пытайся исполнять slash-команды в PowerShell. Не ставь ещё один Claude для установки plugin, если действующий клиент умеет подключать project skills вручную.
4. Для фактического управления Editor предпочтительно **Unity CLI + Unity Pipeline** (экспериментальный CLI; Unity Editor 6+), документация:
   - https://docs.unity.com/en-us/unity-cli/use-unity-cli
   - https://docs.unity.com/en-us/unity-cli/unity-pipeline/unity-pipeline-package
   - https://docs.unity.com/en-us/unity-cli/replace-mcp-server-unity-cli
   Проверь `unity --version`, `unity doctor`. Если CLI отсутствует и поддерживается Windows, официально задокументирован `winget install Unity.CLI` (сначала проверь winget). После входа `unity auth login` при необходимости и только в доступном проекте: `unity pipeline install` и `unity pipeline list`. При наличии shell-доступа `unity command`/`unity eval` могут быть удобнее MCP; если нужен MCP — `unity mcp configure <client>` по текущей документации. Сначала изучи реальное CLI help/документацию, не угадывай параметры. Не устанавливай deprecated in-editor Assistant MCP для новой конфигурации. Резерв: https://github.com/CoplayDev/unity-mcp — только если основной путь не работает. Не запускай оба Unity-моста одновременно.
5. Подключи Blender через https://github.com/ahujasid/mcp-for-blender . Сначала проверь Blender и `uvx`. На поддерживаемой Windows при отсутствии uv предпочитай `winget install --id astral-sh.uv -e` (проверить поддержку). Документирован `uvx mcp-for-blender setup`; он может требовать интерактивного выбора и перезапуска клиента. Прежде чем менять конфиги, сохрани резервные копии. Для MCP выставь `DISABLE_TELEMETRY=true`, `BLENDER_MCP_SAFE_MODE=1` (если не блокирует нужный workflow), `BLENDER_HOST=127.0.0.1`. Blender bridge — не локальная языковая модель; не включай Premium и облачную генерацию 3D. Если мост не подходит, используй `blender --background --python` и проверяемые файлы/рендер, если Blender реально установлен.
6. Сделай настоящие smoke tests, не только проверку наличия команд: **Unity** — новая отдельная сцена `Assets/_FieldClinic/Scenes/FC_ConnectionTest.unity` с изменённым объектом, readback Transform и проверкой Console. **Blender** — тестовый объект в отдельной коллекции, save `.blend` вне Assets, экспорт `.fbx` и реальный импорт в Unity. Отчёт `Docs/SetupReport.md` с PASS/FAIL/BLOCKED/NOT RUN для каждого теста, приложи конкретные пути, команды и ошибки. Перезапуск клиентов/открытие редактора: делай сам, если можешь; иначе попроси одну конкретную операцию пользователя.

Прочитай `03_REPOSITORIES.json` (47 позиций: 34 GitHub репозитория и 13 других источников) и основную исследовательскую часть `02_FULL_GAME_BRIEF.md`. В `Docs/DependencyDecisions.md` классифицируй ВСЕ позиции: `ACCEPTED`, `REFERENCE_ONLY`, `SANDBOX`, `DEFERRED`, `REJECTED`, `BLOCKED`; примени совместимые реальные компоненты только когда понадобятся. Проект не должен ломаться после каждого импорта. НЕ загружай все репозитории и большие ассет-паки сразу.

## C. Создать работающий кусок игры, а не набор технических демонстраций

Минимальная цель одной игровой сцены:
- Дорожная петля/небольшой квартал, база и операционная. Проходимый blockout с габаритами машины и понятными ориентирами.
- Пеший FPS-контроллер. Машина с управлением, посадкой/выходом, переключаемыми камерами первого/третьего лица.
- Один NPC-пациент: обнаружение, попытка убежать, допустимый способ поимки, погрузка в машину, доставка и выгрузка на базу. Никаких двойных наград и дублирующихся живых/прикреплённых к машине персонажей.
- Одна стилизованная абстрактная операция из трёх шагов: выбор инструмента, нажатия по сокетам/областям, завершение с обратной связью. Не вводи реальные хирургические инструкции, насилие ради реализма и жуткий контент без выбора пользователя.
- Базовый свет/звуки, которые меняются после важного события, низкополигональные placeholders и несколько созданных Blender-объектов после настроенного pipeline.
- Сохранение и загрузка состояния. Реальная проверка повторного входа в сцену, режимов камеры, переходов пациента и завершения операции.

Начни с простой, работающей и тестируемой архитектуры, не обещай законченный open-world в одну сессию. Переходи к расширению карты, World Planner, Asset Audit, Operation Validator и измерению 60 FPS только по готовности фундаментального вертикального среза. Реальные измерения CPU/GPU и platform target — только по фактической среде.

## D. Формат самостоятельной работы и отчёт

- Не задавай вопросов о движке, жанре, видеокарте, объёме RAM, опыте пользователя, нейромоделях — ответы уже есть. Действуй по обоснованным дефолтам. Остановись и попроси один конкретный клик/логин/разрешение, только если система без этого не даёт продолжить (UAC, Unity Hub auth, закрыть занятый Editor, разрешить папку). Не предлагай отключать защиты ОС.
- Работай маленькими воспроизводимыми шагами. По окончании каждого тестируй и записывай результат. Уделяй внимание именно функциональности, художественной целостности и производительности; не оптимизируй наугад.
- Веди `Docs/EnvironmentReport.md`, `Docs/SetupReport.md`, `Docs/DependencyDecisions.md`, `Docs/Progress.md`, `Docs/NextAction.md`, `THIRD_PARTY_NOTICES.md`. Для Codex подготовь `AGENTS.md` и project skills; отдельный реальный запуск другого клиента необходим для его проверки.
- В конце фактически достигнутого этапа выдай: **что работает**, **какой scene открыть**, **как управлять**, **что установлено с лицензиями**, **какие реальные тесты выполнены**, **что не получилось и почему**, **точное следующее действие**.
- Если работоспособный локальный Editor недоступен, НЕ пиши «плагин установлен», «работает в Unity» или «тест прошёл». Подготовь файлы и одну точную инструкцию для перехода к локальному Claude Code. Ограничения доступа не решаются одним промптом.
