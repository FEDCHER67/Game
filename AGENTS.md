# Agent guidance

- Inspect `git status` before work.
- Never destroy unrelated changes.
- Never use `git reset`, `git restore`, or `git clean` on unrelated work.
- Never force-push.
- Do not commit unless explicitly allowed.
- Reusable code must not depend on game-specific code.
- Prefer focused tasks.
- Compile/test after code changes.
- Inspect `git diff` before reporting completion.
- Do not claim success without verification.
- Avoid repeatedly scanning the entire repository when focused file search is sufficient.
- The final game concept is not locked. Do not introduce game-specific mechanics, naming, art, or systems until the user explicitly approves crossing the game-specific STOP-GATE.
