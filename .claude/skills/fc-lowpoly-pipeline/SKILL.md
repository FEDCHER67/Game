# Контролируемые low-poly-ассеты

Начни с ArtBible и реальной игровой камеры. Утвержденное пользователем отделяй от предложенного стиля. Low-poly означает выбранный язык форм и управляемую стоимость, а не произвольное уменьшение числа граней.

## Работа

Для каждой модели задай назначение, размеры в метрах, силуэт, movable parts, pivot, материалы, коллайдер, ближайшую дистанцию камеры и ориентир треугольников. Первый комплект: части фургона, стол/каталка, шкаф, лампа, инструменты и модули базы. Не делай 50 декоративных предметов прежде одного законченного цикла.

Используй Blender через доступный мост или воспроизводимый Python. Создавай только свою коллекцию, сохраняй параметры/seed и исходный .blend. Не удаляй чужие объекты. Скриншот viewport обязателен для визуального утверждения; отсутствие Python errors не доказывает качество.

Проверь normals, scale, UV, реальные размеры, точки вращения дверей/колес. Общие материалы и атлас предпочтительнее уникального 4K на каждый предмет. Сохраняй нужный силуэт первого лица. Диапазоны из основного промпта — предлагаемые бюджеты, а не гарантия FPS.

Экспортируй основным выбранным путем; FBX проще для базового импорта, GLB только с подтвержденным процессом. TexTools — внешний Blender-инструмент; MeshSimplifier — офлайн-кандидат для LOD с сохранением оригинала. Никогда не перегенерируй .meta бесконтрольно.

## Приемка

Unity Asset Audit: фактические треугольники каждого LOD, submeshes/materials, bounds, текстуры, коллайдеры и missing references. Проверить вид с игровой камеры, тени, LOD-переход и движение частей. Не называть расчетный размер текстуры измеренной памятью GPU.
