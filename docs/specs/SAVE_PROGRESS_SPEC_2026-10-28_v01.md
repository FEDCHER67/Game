# VOLUNTEERS ONLY — сохранения и восстановление мира

Дата: 28.10.2026. Версия: v01. Спецификация, без реализации и работы с настоящими сейвами.

## 1. Принятые правила и границы

Confirmed Q3–Q5: пять отдельных миров, ручное сохранение в любой момент, автосохранение и резервные версии; разрешён целостный откат через загрузку. Незатронутая толпа может восстановиться по населению/часу, изменённые личности/предметы/последствия сохраняются. Остальные параметры ниже Proposed по делегированию. Это дополнение [NETWORK](NETWORK_MAP_PLAN_v01.md), [инвентаря](WORK_INVENTORY_SPEC_2026-10-18_v01.md), [экономики](ECONOMY_SALES_PROGRESSION_SPEC_2026-10-25_v01.md), [миссий](STORY_MISSIONS_SPEC_2026-10-28_v01.md) и [PHONE](PHONE_SPEC_2026-10-18_v01.md), не новый параллельный формат игры.

Хост владеет сохранением. Клиентские стабильные GUID до Steam сохранены; уход хоста завершает сессию, без host migration. Нет обязательного облака/Steam-синхронизации или переноса имущества между мирами.

## 2. Пять миров и интерфейс

Proposed: список из пяти слотов. В каждой карточке название, время последнего успешного сохранения, активное игровое время, сюжетный этап, уровень команды и наличие резервных версий. Имя меняет только метаданные; WorldId постоянен. Пустой слот создаёт новый WorldId и отдельные деньги/инвентари/флаги. Пять миров не означают пять персонажных кошельков одного мира.

Внутри каждого мира: текущая ревизия и три сохранённые прошлые игровые версии. Proposed: последняя ручная контрольная точка защищена от вытеснения очередным автосохранением и занимает одно из этих трёх мест, когда отличается от текущей; остальные места — последние целые фоновые версии. Новое ручное сохранение заменяет защищённую точку. Если ручной точки ещё нет, все три места доступны фоновой истории. Финансовый коммит не прокручивает историю UI на каждую продажу: это долговечный журнал/согласованная запись внутри мира, а не обязательный новый видимый снимок.

Технический временный файл/последняя целая копия атомарной записи не показываются как дополнительные прохождения и не занимают другие четыре слота. Три версии — ограниченная история, не бесконечный архив. Клиент не создаёт собственный сейв общей сессии. Proposed: любой участник может запросить ручной снимок у сервера; пишет только хост в текущий мир, без клиентского выбора другого слота/загрузки. Повторные одновременные запросы объединяются, не создавая три одинаковые резервные копии.

Ручное сохранение не требует базы, окончания погони, отпущенного NPC, остановки операции или закрытого заказа. Запрос снимает согласованное состояние в ближайшей безопасной границе серверного тика/транзакции, без остановки мира на неопределённое ожидание. Если запись не удалась, прежняя целая версия остаётся, UI сообщает ошибку и не пишет «Сохранено». Не перехватывать для этого ввод живой процедуры.

Загрузка/перезапись занятого мира требует явного подтверждения с названием и временем выбранной ревизии. Перед загрузкой в кооперативе хост видит предупреждение о завершении текущей сессии; клиенты отключаются штатно. Клиент не может загрузить другой мир всем участникам. Удаление мира — отдельное явно подтверждённое действие игрока в игре, не часть этой документальной задачи.

## 3. Когда сохранять

| Событие | Proposed или унаследованное поведение |
|---|---|
| Ручной запрос | В любой момент, целостная ревизия. |
| Фоновый снимок | Каждые 60 активных реальных секунд, как в NETWORK §3.8; не раз в игровую минуту. |
| Экономический/уникальный сюжетный коммит | Надёжно фиксируется в момент успешной транзакции; не ждёт фоновой минуты. |
| Открытие/закрытие мирового этапа | Согласуется с той же ревизией фонда/предметов/заказа, не отдельным опережающим флагом. |
| Вход/выход клиента | Состояние GUID и владение; не новая награда и не обнуление срока. |
| Штатный выход хоста | Сначала успешное сохранение согласованного мира, затем завершение сессии. Ошибка записи не маскируется успешным выходным сохранением. |
| Аварийное завершение | Восстановление последней целой ревизии и согласованных долговечных коммитов; не обещание сохранения каждого физического кадра. |

Не накапливать очередь из десятков одинаковых фоновых сохранений; один активный снимок и объединённый запрос следующего. Время закрытого мира не тикает. В активной сессии выход одного клиента не останавливает время/порчу его сохранённого имущества по действующим правилам.

## 4. Что сохраняется

| Блок | Требуемое состояние |
|---|---|
| Мир | WorldId, ревизия схемы/контента, номер целостного снимка, временная ветка, игровые день/час и накопленное активное время. |
| Экономика | Один фонд, записи/защита от повторов, заказы и переговоры, респект/насыщение, время электричества, сотрудники/долги, доставки. |
| Прогресс | Пожизненный/свободный XP, личные навыки/вклад, уровень, контактные этапы, 3/7 встреч, completed-миссии/VIP и состояние постфинала. |
| Предметы | Один ledger экземпляров, владельцы/контейнеры/слоты, позы свободных вещей, contents, retired IDs, шприцы/привязки, качество/упаковка/холод/дробная порча. |
| Игроки | Блок по GUID: положение/ориентация, валидное место в машине, выбор кармана, все удерживаемые вещи через ledger, состояние по действующему игровому контракту. |
| Бусик | Положение/движение, двери, принадлежность, оплаченные ступени/кузов/полка, покраска и ссылки на её данные. |
| Значимые NPC | PersonId, capture/PatientId, происхождение/состояние, кровь, наркоз/сон/стяжки/мешок, смерть/открытие/порча, поза/место и назначение сюжетной личности. |
| Операционная | Столы/пациенты, четыре крепления, открытия/костные точки/соединения/извлечённые органы, шов/заплатка/ошибки/мусор и уборка. |
| Последствия | Тела, предметы-улики, грязь/отходы, значимая память свидетелей и полицейское состояние по их владельцу. |
| Телефон | Согласованные контакты/переписки/чтение/навигация и ограниченная видимая история; действующие финансовые tombstones не стираются лимитом ленты. |

Удержание NPC и предмет в кармане — разные сущности: уход несущего освобождает тело по CAPTURE, но карманные вещи отсутствующего клиента остаются в его сохранённом владении. Предмет не сериализуется полностью и в кармане, и в контейнере. Тайник старого дня сохраняет возвратные секции/отметки; ежедневная смена или загрузка не удаляет оставленное.

Сохранение посреди взаимодействия фиксирует уже выполненный прогресс, а не зажатую кнопку ввода. После загрузки transient-захваты/курсоры восстанавливаются в безопасное нейтральное управление; предмет/пациент не клонируется и оплаченный шаг не повторяется. Не объявлять такую загрузку побитовым повторением всех кадров физики.

## 5. Обычная толпа и значимые изменения

Незатронутому обычному прохожему не обещано прежнее точное место/занятие после загрузки; районный профиль и час восстанавливают правдоподобное население. Нельзя одновременно восстановить сохранённого изменённого NPC и породить его обычную копию.

Значимым становится NPC после захвата/повреждения/крови/распознанного вмешательства со сохраняемой памятью, сюжетной привязки, скана заказа, смерти/извлечения либо иной необратимой операции. Авторитетная система определяет набор сохраняемых полей; нельзя назвать свидетеля «обычным незатронутым» ради очистки сообщения/подозрительности. Восстановление района учитывает уже занятые/исключённые личности и tombstones. Новая популяционная личность не получает donor ID убитого персонажа.

Точный полный жизненный распорядок не нужен. Приоритет и переходы — [NPC](NPC_SCHEDULES_INTEGRATION_SPEC_2026-10-28_v01.md). Никакой автоматической уборки тел/отходов/розыска при перезапуске или достижении уровня.

## 6. Целостный откат и аварийное восстановление

Разрешение ручного отката — явное игровое решение Q4. Оно означает загрузку **всего прошлого мира**: денег, предметов, жертв, XP, миссий, счётчиков и сроков. Нельзя взять ранние предметы вместе с будущими деньгами/наградами или переслать послеперезапусковый клиентский запрос как продолжение старой сессии.

Proposed контракт ревизии: каждый снимок хранит согласованный watermark применённых транзакций. При обычном аварийном восстановлении можно доиграть только долговечные коммиты той же ветки, для которых есть полный предметный/денежный исход. При намеренной загрузке выбранной старой версии будущий журнал к ней не приклеивается: возникает новая временная ветка, устаревшие запросы прежней сессии отклоняются. Retired/completed-флаги сохраняются внутри выбранной ветки; нельзя объединять старый предметный снимок с будущими tombstones или выборочно импортировать фонд.

Так повтор уникального задания после полного отката может произойти в более раннем мире, но награда не складывается с отменённым будущим. «Один раз на сохранение» означает один действующий исход в текущей целостной истории, а не внешний несбрасываемый аккаунтный бонус. Фотографии/локальные настройки игрока не импортируют экономику из будущего.

Нельзя продолжать активную сессию, пока хост читает другой снимок, и дописывать покупки к новой ветке. Выбранный источник загрузки закрепляется до выходного автосохранения, чтобы не перезаписать именно ту резервную версию, которую запросил игрок.

## 7. Запись, совместимость и ошибки

Использовать существующий путь сохранения и атомарную замену временного файла целым, не второй несвязанный cash-файл. Новый формат имеет явные версии блоков и миграции; пример старого `CaptureSaveData` v1 и предлагаемый v2 не означают, что миграция уже реализована.

Старый слот читается через миграцию с сохранением подтверждённых денег/имущества/прогресса; неизвестное поле получает документированное значение, не нарисованную награду. Если принадлежность/донор неизвестны, не выдумывать пригодность для VIP. Фонд legacy переносится один раз по экономике, не из банка-заглушки. Старые оплаченные ступени сохраняются, debug-max не становится оплаченной покупкой и не ослабляется молча.

Сейв более новой неподдерживаемой версии нельзя загрузить частично и затем затереть старым писателем. Показать несовместимость и оставить файл. При повреждении текущего — предложить последнюю валидную версию с датой/предупреждением о потерянном отрезке. Все версии повреждены — объяснить ошибку, не создавать «новую игру» поверх них автоматически.

Переименование мира не меняет WorldId. Новая игра в другом слоте не копирует деньги/профессии. Переход GUID→Steam требует отдельной однократной связи идентичности, не двух блоков с одним инвентарём. Локальные скриншоты/галерея/графические настройки не становятся общими экономическими данными.
