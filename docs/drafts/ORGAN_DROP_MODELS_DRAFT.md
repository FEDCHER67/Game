# Выброшенные предметы — настоящими моделями (черновик)

Статус: черновик, ветка `cloud/organ-drop-models`. Код не компилировался в Unity и не проверялся в игре (в облачной сессии нет редактора). Перед слиянием нужны компиляция, плейтест офлайн-сцены и сетевой тест (хост + клиент).

## Что хотел Федя

Предмет, выброшенный из инвентаря на G, должен падать в мир своей 3D-моделью (сердце — моделью сердца, почка — почкой, пачка денег — пачкой), а не серым кубиком, и его можно снова подобрать на E.

## Как было

- `OfflineWorldItem.Spawn` (офлайн, `LocalInventory`) создавал куб 0,3 м с Rigidbody 1 кг.
- `NetworkInventory.ServerDrop` (сеть) требовал у предмета собственный сетевой префаб `ItemDefinition.worldPrefab`; у всех предметов он пустой, поэтому в сети выбросить ничего нельзя.
- Модели органов знал только редакторный `MapGreyboxBuilder.SpawnPickup` (словарь «имя → FBX» в `Assets/OnlyVolunteers/Props/Organs`), и только для пикапов, расставленных на карте.

## Что сделано

### Данные предмета (`ItemDefinition`)

Новый блок полей «World model (dropped item)»:

| Поле | Смысл | По умолчанию |
|---|---|---|
| `worldModel` | префаб или импортированный FBX, которым предмет лежит в мире | пусто → серый кубик 0,3 м (запасной вариант) |
| `worldModelSize` | самая длинная сторона модели в метрах; 0 = родной размер | 0,3 |
| `colliderShape` | Auto / Box / Sphere / Capsule. Auto: капсула вдоль длинной стороны для вытянутых предметов, иначе коробка | Auto |
| `dropMass` | масса Rigidbody офлайн-дропа, кг | 0,4 |
| `dropBounciness` | упругость (0 — шлепок, 1 — мячик) | 0,3 |
| `dropSquish` | насколько модель сплющивается при ударе (0 — твёрдая) | 0,2 |

Выбран вариант «префаб/FBX», а не «меш + материал»: FBX органов многосоставные и уже несут свои материалы, а один `GameObject` покрывает оба случая.

### Общий построитель модели (`ItemWorldModel`, новый файл)

Один код для офлайна и сети. Создаёт у объекта дочерний `WorldModel`:
- копия `worldModel` (или куб, если модели нет); собственные коллайдеры модели снимаются;
- масштаб по рендерерам до `worldModelSize`;
- модель центрируется (офлайн) или ставится низом на точку опоры (сеть — сервер кладёт предмет на пол);
- один подогнанный по габаритам коллайдер (Box/Capsule/Sphere). Офлайн — твёрдый с физ. материалом: трение 0,8/0,9 (Maximum — не скользит), упругость из предмета (Maximum — отскок на любом полу). В сети — триггер, только для луча подбора.
- `AddPhysics`: Rigidbody с массой предмета, демпфирование 0,2 / угловое 1,5 (не катится бесконечно), интерполяция, ContinuousSpeculative (маленькие быстрые предметы не проваливаются).

### «Мягкость» (`SquishOnImpact`, новый файл)

Чисто визуальный компонент: при ударе быстрее 0,8 м/с модель сплющивается (до `dropSquish` при 5 м/с) и затухающе колышется ~0,3 с. Масштабируется только дочерняя модель, коллайдер и тело не трогаются. Цифры подобраны на глаз — нужен плейтест.

### Офлайн (`OfflineWorldItem`, `LocalInventory`)

- `OfflineWorldItem.Spawn` теперь строит корень + `ItemWorldModel` + Rigidbody, добавлен необязательный параметр `velocity` (старые вызовы компилируются как раньше). Небольшое случайное вращение, чтобы два одинаковых органа падали по-разному.
- `LocalInventory.RequestDropSelected`: предмет появляется в 1 м перед игроком на высоте ~1,1 м (было 0,3 м) и подбрасывается вперёд со скоростью `dropThrowSpeed` (новое поле, 1,5 м/с) и 0,5 м/с вверх.
- Подбор не менялся: `OfflineWorldItem.Nearest` ищет по позиции корня, а Rigidbody стоит на корне, так что упавший и откатившийся орган подбирается на E как раньше (и через `GreyboxInteractor`).

### Сеть — изменения в файлах Вадима

Логика сервера (проверки RPC, дальность, расчёт точки сброса, `ServerSetContents`, события) сохранена. Изменено ровно следующее:

1. **`ItemDatabase.cs`**
   - новое поле `genericWorldPrefab` (NetworkObject с `WorldItem` без своего definition);
   - метод `WorldPrefabFor(item)`: собственный `worldPrefab` предмета, иначе общий; `null`, если нет ни того, ни другого.
   - добавлен `using FishNet.Object;`.
2. **`NetworkInventory.cs`, только `ServerDrop`**
   - префаб берётся через `database.WorldPrefabFor(definition)` вместо `definition.WorldPrefab`; проверка «есть `WorldItem` в префабе, иначе предупреждение и отказ» та же;
   - после `Instantiate` и до `Spawn` добавлен вызов `worldItem.ServerSetDefinition(definition)` (рядом с уже существующим `ServerSetContents`, тот же приём «задать SyncVar до спавна»).
   - Если у предмета есть свой `worldPrefab`, поведение полностью прежнее.
3. **`WorldItem.cs`**
   - поле `database` (нужно только общему префабу) и `SyncVar<int> itemId` — id предмета, который сервер задаёт общему префабу; у префабов со своим definition остаётся 0 и ни на что не влияет;
   - `Definition` стал свойством: свой definition, иначе предмет из базы по `itemId`. `ServerPickup` использует его как раньше, включая проверку `database.Get(id) == definition`;
   - `OnStartServer`: базовая цена берётся из `Definition` (раньше из поля напрямую — для префабов со своим definition результат тот же);
   - новый `ServerSetDefinition(item)` — только сервер, между Instantiate и Spawn, игнорируется, если у префаба свой definition;
   - `OnStartClient`/`OnStopClient` + подписка на `itemId.OnChange`: на клиенте (и на хосте) строится модель через `ItemWorldModel` с триггер-коллайдером — его находит луч `FindWorldItem`. Если в префабе уже есть свои рендереры, ничего не строится.
   - Физики в сети нет, как и раньше: сервер сам кладёт предмет на пол (`floor.point + 0.05`), модель выровнена низом по точке опоры. Падение/отскок в сети потребовали бы NetworkTransform или предсказание — это решение за Вадимом.

Трафик: +1 SyncVar<int> на каждый выброшенный предмет.

### Редакторное меню (`Inventory/Editor/ItemWorldModelMenu.cs`, новая сборка `OnlyVolunteers.Inventory.Editor`)

- **OnlyVolunteers → Inventory → Assign Item World Models** — проходит по `ItemDatabase` и заполняет пустые `worldModel` по имени предмета теми же FBX, что и `MapGreyboxBuilder.SpawnPickup`: Heart, Kidney, Liver, Lungs, Brain (Props/Organs), Scalpel (Props/ScalpelAstra). Размер 0,45 м — как у пикапов на карте, чтобы орган выглядел одинаково до и после переноски. Масса/упругость/мягкость — заглушки до плейтеста (сердце 0,35 кг, почка 0,2, печень 0,6, лёгкие 0,5, мозг 0,45, скальпель 0,1 без мягкости). Уже заданные вручную модели не перезаписываются; в консоль пишется отчёт.
- **OnlyVolunteers → Inventory → Create Generic WorldItem Prefab** — создаёт `Items/WorldItem_Generic.prefab` (NetworkObject + WorldItem с базой) и прописывает его в `ItemDatabase.genericWorldPrefab`. После этого нужно убедиться, что префаб попал в `Assets/DefaultPrefabObjects.asset` (FishNet обычно добавляет сам при импорте). Это отдельная команда, чтобы Вадим решил, нужен ли общий префаб.

Сами ассеты (`Item_*.asset`, `ItemDatabase.asset`, префаб) в этой ветке не менялись — меню запускается в редакторе.

## Чего нет / открытые вопросы

- **Глаз (Eye)**: модель есть только в `ArtSource/Props/EYE-ASTRA-001`, в Assets не импортирована. Меню подхватит её, если скопировать в `Assets/OnlyVolunteers/Props/Organs/EYE_ASTRA_001_v03.fbx`. Пока глаз падает серым кубиком.
- **Деньги (пачка)**: предмета «наличные» нет — деньги в инвентаре это число (`Cash`), и G выбрасывает только предмет из слота. Модель `ArtSource/Props/CASH-ASTRA-001` тоже не импортирована. Меню готово к предмету с именем `Cash` (путь `Assets/OnlyVolunteers/Props/Cash/CASH-ASTRA-001.fbx`), но заводить предмет-деньги и решать, как выбрасывать наличные (вся сумма? пачками?), — это решение по геймдизайну, не сделано.
- **Пикапы карты** (`MapGreyboxBuilder.SpawnPickup`) не трогал: они по-прежнему статичны, без коллайдера и Rigidbody, со своим словарём моделей. Можно позже перевести их на `ItemWorldModel`, чтобы был один источник моделей.
- Размер 0,45 м для органов — игровой, а не анатомический (реальное сердце ~12 см). Если нужно реалистичнее — поменять `worldModelSize`.

## Что проверить (обязательно перед слиянием)

1. Компиляция в Unity 6000.5.11f1 (код писался без редактора).
2. Запустить меню Assign Item World Models, проверить отчёт и что у органов заполнились модели.
3. Офлайн-сцена (карта grey-box): взять орган, G — падает моделью, отскакивает, сплющивается, не проваливается, не укатывается; E — подбирается; цена сохраняется.
4. Предмет без модели (Eye) падает серым кубиком и подбирается.
5. Сеть: Create Generic WorldItem Prefab, проверить DefaultPrefabObjects; хост + клиент: G на клиенте — у обоих видна модель органа на полу; E подбирает; на выделенном сервере модель не строится.
6. Субъективно: размер, мягкость, отскок — плейтест Феди.
