# Работа вдвоём и синхронизация

## Общая версия

GitHub: https://github.com/FEDCHER67/Game. Основная ветка — main. Unity **6000.5.11f1**; обязателен Git LFS.

Git синхронизирует исходники, модели, документацию, Assets с .meta, Packages и ProjectSettings. Library, Temp, Logs, UserSettings, сборки и файлы IDE создаются отдельно на каждом ПК. Их побайтовое совпадение не нужно.

Pull не удаляет посторонние untracked/ignored файлы и не отменяет локальные изменения. Отсутствие конфликтов гарантировать на неизвестном checkout нельзя. Нужна чистая общая ветка без локального расхождения.

## Обновить существующую чистую папку

Закрыть Unity. Сначала проверить:
```powershell
git status --short
git branch --show-current
```

При локальных изменениях остановиться и разобрать их. Для чистого checkout:
```powershell
git switch main
git pull --ff-only origin main
git lfs pull
git lfs fsck
git rev-parse HEAD
git rev-parse origin/main
git status --short
```

Два хеша должны совпадать, status должен быть пустым. Если --ff-only отказывается обновлять — ветки разошлись; не лечить это автоматическим reset/clean/force push. Старые ignored-кэши и сборки могут остаться: Git их не обслуживает.

Если нужна папка вообще без старых посторонних файлов, альтернатива — загрузка в ещё НЕ существующий каталог назначения:
```powershell
git lfs install
git clone https://github.com/FEDCHER67/Game.git GAME
git -C GAME lfs pull
git -C GAME lfs fsck
```

Это способ начать с чистой версии, не инструкция удалять чужую работу или делать бэкап. Открывать Unity после загрузки LFS, не обновлять Editor/пакеты попутно.

## Как Федя сдаёт модели

1. Получить свежую main. Одна модель — одна новая ветка от неё, например fedya/prop-lamppost-01.
2. Работать только в папке назначенной модели. Не изменять общие спецификации.
3. Закоммитить модель, экспорт, превью и карточку. Проверить LFS и отсутствие .blend1/временных файлов.
4. Отправить СВОЮ ветку на GitHub. Сообщить имя ветки, исходный коммит и что проверено.
5. В этом основном чате проверяем модель и объединяем принятую работу в main. После этого все обновляют main.
6. Интеграция модели в Unity — отдельная задача основного чата.

Федя не пушит рабочие изменения прямо в main. Не отправлять незавершённые изменения под видом готового ассета. Префикс ветки — соглашение, не настройка защиты GitHub.

## Области ответственности

Федя: только ArtSource/Environment/<ModelId>/ или другая явно назначенная папка исходников. Разные модели — разные папки.

Основной чат: канон/спецификация, код движения и физики, сеть, общие сцены/префабы, регистрация объектов, Packages, ProjectSettings и импорт в Assets.

Не создавать для каждой модели отдельный Unity-проект внутри GAME. Никаких новых менеджеров, скриптов захвата, кастомных пакетов и глобальных настроек в задаче на модель.

Даже изолированные задачи влияют на продукт через масштаб/стиль; эти требования фиксируются в карточке. Полностью независимых от проекта задач нет.

## Старые ветки

Новые работы начинать от обновлённой main, а не от старых worker/* или codex/*. Иначе объединение может вернуть удалённые файлы и прежнюю агентскую систему.

На момент ревизии отдельно существует codex/gurney-grab-20260930 (54aacff): более новые изменения поведения каталки относительно консолидированного 892d7ca. Их ещё предстоит отдельно оценить; они не входят в очищенную основу автоматически. Ветка codex/project-skills-20260930 также не включается целиком.

Не обещаем математическое отсутствие merge-конфликтов. Раздельные папки, короткие ветки и один интегратор резко уменьшают риск.
