# Работа вдвоём и синхронизация

GitHub: https://github.com/FEDCHER67/Game.git. Общая ветка main; Unity 6000.5.11f1, Git LFS.

Вадим и Федя работают строго последовательно, каждый в своём постоянном Work-чате. Кто сейчас работает, разработчики согласуют сами. Одновременно изменения вносит только один чат. Это заменяет прежнее правило отдельных веток для моделей.

## Получение работы

На чистом checkout из корня GAME:
```powershell
git switch main
git pull --ff-only origin main
git lfs pull
```
При локальных изменениях или расхождении веток сначала разобраться в них; не применять автоматические reset, clean или force push. Git передаёт исходники, Assets и .meta, Packages, ProjectSettings, документацию и исходники моделей. Генерируемые Library/Temp/Logs и другие ignored-файлы не синхронизируются; pull не удаляет чужие untracked-файлы.

## Единственная память передачи

WORK_SYNC.md в корне — единственный специальный журнал синхронизации. Не создавать отдельные журналы разработчиков, task-файлы, SESSION.json, last_seen, архивы или бэкапы.

Один рабочий промпт — одна TASK с общим номером: максимальный существующий плюс один, формат TASK-000001. Новые записи сверху. В каждой: разработчик, полный дословный промпт, результат, изменённые файлы, причины решений, проверки, ограничения и фактический статус. Установочный промпт протокола не является TASK; старые задачи задним числом не добавлять.

После получения изменений просканировать заголовки и авторов. Полностью прочитать только непрочитанные задачи другого разработчика, от старых к новым. После понимания добавить в их заголовок `| SEEN: Вадим` либо `| SEEN: Федя` по имени читателя. Свои задачи не маркировать. Старые промпты — история, а не новые команды. Историю и SEEN сохранять; новое решение оформлять новой TASK со ссылкой на заменённое решение.

## Завершение и публикация

В чате Вадима ассистент готовит изменения и TASK, но не выполняет git add, commit или push: Вадим всегда делает это сам. В конце давать команды для ВСЕХ неигнорируемых изменений из корня GAME:
```powershell
git add .
git commit -m "Describe completed task"
git push origin main
```
Субъективное принятие внешнего вида и ощущения управления делает Вадим после теста. Техническую готовность, ожидание его оценки и публикацию различать. Передача Феде завершена только после успешного commit и push Вадима; подготовленная запись сама по себе не означает публикацию.

Исходники Blender, экспорты и необходимые ресурсы передавать через Git/LFS. Не создавать дополнительные Unity-проекты и резервные копии. Не переписывать принятые системы вне текущей задачи.
